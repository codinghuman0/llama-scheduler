## Counter definition

For every numbered `cpuN` row, read fields in this order:
`user nice system idle iowait irq softirq steal guest guest_nice`.
The aggregate `cpu` row is ignored. At least the first four fields are
required; absent later fields are zero. Extra future fields are not added.

```text
idle_all = idle + iowait
non_idle = user + nice + system + irq + softirq + steal
total = idle_all + non_idle
Dtotal = total_B - total_A
Didle = idle_all_B - idle_all_A
util_percent = 100 * (Dtotal - Didle) / Dtotal
```

`guest` and `guest_nice` are already accounted in user/nice and are not added
again. CSV utilization has one canonical unit: **percent, 0..100**. Deltas are
USER_HZ ticks, not nanoseconds; metadata records `os.sysconf('SC_CLK_TCK')`.
Do not divide by a presumed 100 ms or infer utilization from one snapshot.

If any of the first eight counters regresses, or `Dtotal <= 0`, utilization is
blank with `valid=0` and an explicit `reason`; raw aggregate deltas remain.
Missing/new CPUs are invalid until two adjacent observations are available.
The next observation always rebases onto the latest counters.
Regressing iowait is possible; see the
[Linux /proc documentation](https://www.kernel.org/doc/html/latest/filesystems/proc.html).
Invalid rows are never silently clamped to 0% or 100%.

This is an interval accounting signal. The kernel documents accounting
limitations in [CPU load](https://www.kernel.org/doc/html/latest/admin-guide/cpu-load.html).
At 100 ms, counter quantization and ordinary system noise are expected.
Steal counts as non-idle in this definition; iowait counts as idle by convention.
Utilization cannot attribute execution to a particular process.

## Sampler and CSV

```sh
python3 scripts/sample_cpu_util.py --interval-ms 100 --duration 40 \
  --cpus all --output /tmp/m10b-samples.csv
```

Use `--cpus 2,4` for selected CPUs. IDs must exist in `/proc/stat` at startup;
malformed or absent IDs fail clearly. `all` follows the CPUs present in each
snapshot. A hotplug disappearance/reappearance produces invalid transition
rows; it does not cause a fabricated valid delta. No root interface is used.
Output must be a new file; its parent must exist.

CSV columns:

```text
sample_index,monotonic_ns,elapsed_ms,interval_ns,read_duration_ns,cpu,util_percent,delta_total_ticks,delta_idle_ticks,valid,reason
```

- Initial snapshot is the reference only; the first CSV sample is index 1.
- One row per CPU per interval; sample index and timing repeat for those CPUs.
- `time.monotonic_ns()` is taken before and after reading `/proc/stat`.
  `monotonic_ns` is their midpoint; `read_duration_ns` exposes read uncertainty.
  The read is not an atomic simultaneous snapshot of all CPUs.
- `elapsed_ms` is relative to the initial snapshot midpoint.
- `interval_ns` is the actual difference between consecutive midpoints.
  Interval start is exactly reconstructible as `monotonic_ns - interval_ns`.
- Deadlines are anchored to the initial reference, nominally every 100 ms.
  Missed deadlines are skipped, so there are no catch-up bursts. The final
  sample can be shorter or late; no assumption of exactly 100 ms is made.
- Rows are flushed each sample. Interruptions preserve completed rows.

## First controlled validation (manual, unprivileged)

From the repository:

```sh
m10b_run="results/m10b/$(date -u +%Y%m%d-%H%M%S)-step"
python3 scripts/run_m10b.py run --stress-cpus 2,4 --output-dir "$m10b_run"
cat "$m10b_run/summary.csv"
```

The runner samples all CPUs at 100 ms, waits 10 s baseline, launches two
100% workers confined to CPUs 2,4, requests their termination after 20 s,
then samples at least 10 s recovery. It inherits a SCHED_OTHER caller and
explicitly requests `--sched other` for stress-ng. It never changes the
caller policy. Requested CPUs must also be in the caller's allowed mask.

Exact command launched by the default runner:

```sh
/usr/bin/stress-ng --cpu 2 --cpu-load 100 --taskset 2,4 --sched other --timeout 25s
```

The 25 s timeout is a fallback. The helper sends SIGINT to its own stress
process group after the measured 20 s deadline. This group includes its
workers. Ctrl+C and SIGTERM trigger the same cleanup, with a bounded SIGKILL
fallback; unrelated stress-ng processes are never targeted. The shared mask
allows workers to migrate between CPUs 2 and 4; it is not a one-worker-per-CPU
assignment. A direct independently launched 20 s stress command is:

```sh
/usr/bin/stress-ng --cpu 2 --cpu-load 100 --taskset 2,4 --sched other --timeout 20s
```

Use the helper for the first run to preserve correlated event boundaries.
Durations are nominal, checked at sampling ticks; launch, shutdown, and
userspace delays can extend the run by a few samples. Use measured event
times rather than hard-coded elapsed 10/30 s boundaries during analysis.
SIGKILL of the runner cannot be handled; the stress-ng timeout remains its
finite fallback. A failed/early stress child aborts the experiment.

A new output directory is required. Outputs:

| File | Purpose |
| --- | --- |
| `samples.csv` | Per-CPU utilization, deltas, timestamps, validity |
| `events.csv` | Same-clock experiment/start/stop/recovery/abort events |
| `metadata.json` | Kernel, version, affinity, stress CPUs, timings, exact argv |
| `stress-ng.log` | Preserved stdout/stderr |
| `summary.csv` | Per-CPU baseline/stress/recovery means and valid/invalid counts |

Events distinguish launch request, launcher return, stop request, and child
exit observed after wait. These are userspace control boundaries, not exact
worker execution timestamps. Worker startup/shutdown has finite latency.

Summary windows are baseline_start..stress_start,
stress_launched..stress_stop_requested, stress_stop..recovery_end. Only
intervals fully inside a window are used; transition intervals are excluded.
Means are weighted by actual interval duration, with valid covered time in
milliseconds; no significance test or automatic scientific PASS is claimed.
Invalid samples are counted and excluded. No valid observations means a blank
mean. Incomplete/aborted runs cannot be summarized as completed runs.
The `summarize OUTPUT_DIR` subcommand can create a missing summary; it refuses
to overwrite an existing one.

Inspect CPUs 2 and 4 for a clear rise during stress and fall during recovery.
Compare with all non-selected CPUs while allowing system noise and SMT effects.
If unclear, inspect events, invalid rows, and stress logs, then repeat M10B.
