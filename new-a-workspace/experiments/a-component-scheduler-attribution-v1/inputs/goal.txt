[2. 비교군 — 이름과 실제 구성 고정]

B0_L: 보존된 역사적 B0 재빌드 + Linux.
F6_L: 같은 A runtime/DSO + Linux, NEWA_DECODE_RESOURCE=fixed6.
A_L: 같은 A runtime/DSO + Linux, NEWA_DECODE_RESOURCE=pressure.
A_S: 같은 A runtime/DSO + pressure + 사전에 선택·고정한 기존 연구용 scheduler S.

F6_L은 custom Q4/Q6와 semantic phase 전달, Prefill 센서, 유효성·task 연속성 검사, bounded evidence를 모두 유지하고, 적격 multi-token Decode에서 선택만 고정6으로 대체한다. 원래 single-token5 및 MIXED/UNKNOWN fallback은 보존한다. 기존 helper가 실제로 이 의미인지 소스와 기능 실행으로 확인한다.

NEWA_DECODE_RESOURCE=off 또는 marker 제거를 fixed6 ablation으로 사용하지 마라. off의 기존 profile 경로는 다른 결정을 할 수 있다. HINT/marker는 CPU backend phase bridge와도 연결되어 있으므로 끄지 않는다.

F6_L/A_L은 environment mode 한 항목 외에 같은 실행 파일·DSO·자원을 사용해야 한다. fixed6이 현재 동결 바이너리에 없다면 별도 blocker로 보고하고, 사후에 arithmetic/server patch를 묵시적으로 추가하지 않는다.

S는 현재 보존된 AMD fixed-affinity 검증 후보 하나를 식별하고 timing 전에 고정한다. 최신 원격 저장소로 교체하거나 여러 scheduler를 돌려서 잘 나온 것만 선택하지 않는다. 현재 observe와 팀원의 E FULL을 같은 것으로 가정하지 말고 실제 source·매크로·ELF·guard를 명시한다. 기존 선택을 찾을 수 없거나 현재 kernel에서 안전 검증을 못 하면 S를 BLOCKED로 남긴다.

필수 직접 비교:
- A_L / B0_L: 이번 캠페인의 전체 runtime 효과 확인. 이전 수치는 참고만 한다.
- F6_L / B0_L: 이번 적응 선택을 제외한 구성의 누적 효과. 센서 등은 남으므로 순수 kernel만의 효과라고 부르지 않는다.
- A_L / F6_L: 같은 센서/검사 비용을 유지한 적격 Decode 선택의 효과.
- A_S / A_L: 동일 userspace 정책에 기존 scheduler를 추가한 효과.
- A_S / B0_L: scheduler 포함 최종 조합의 원본 대비 직접 성능.

A_S에서 E의 실제 worker 선택이 A_L과 달라지면 그 효과에는 scheduler와 E의 상호작용/매개 효과가 포함된다. 같은 userspace 정책의 구성 요소 추가 효과라고는 말할 수 있지만, 고정된 worker 실행에 대한 순수 dispatch 효과로 제한하여 주장하지 않는다. 선택이 다르다는 이유로 표본을 삭제하거나 threshold를 바꾸지 않는다.

이 설계에는 S의 fixed6 arm이나 fixed5 대조군이 없다. 따라서 scheduler×E 상호작용의 완전한 요인 분해나 모든 정적 worker 구성 대비 적응 정책의 우월성을 입증한 것이라고 쓰지 않는다.

[3. S 기능 admission을 timing보다 먼저 끝내라]

모든 빌드/추론/runner는 일반 계정으로 수행한다. 승인된 기존 loader·BPF 진단·자신의 cleanup에 필요한 권한만 사용한다. 필요한 인증은 기존 절차를 따르며 password 저장, sudoers 수정, 비밀번호 없는 root 우회, 시스템 전역 스케줄링, unrelated process 종료는 금지한다. 저장소가 요구하는 별도 승인 경계를 넘지 않는다.

고정 CPU envelope에서 다음을 기능 검사한다.
- 실제 kernel/BTF/boot, topology, 라이브러리, executable, 모델 identity.
- loader/launcher는 기존 정상 정책, 선택 server/worker는 실제 SCHED_EXT, 부하 generator 및 unrelated tasks는 기본 Linux.
- 정확한 BPF object와 scheduler instance의 실제 활성 상태, matching marker ELF/PID 범위 attachment.
- 실제 Prefill/Decode marker 수신. 저장만 하는지 실제 배치 결정을 바꾸는지 소스/매크로/동작으로 구분.
- expected output, zero mask violation/tracking failure, watchdog/timeout, detach와 최종 disabled.
- stale identity, 비정상 종료, 적용되지 않음, fallback/detach는 기존 안전 기준대로 실패 처리.

phase_seen이나 uprobe attach 자체를 phase-aware scheduling의 성능 증거로 취급하지 않는다. S가 observe/phase-independent라면 그렇게 기록한다. 이 goal에서 handoff 매크로를 새로 켜거나 phase 상태 수명 동작을 바꾸지 않는다. 과거 dynamic-affinity strict failure를 fixed-affinity 성공으로 해제하지 않는다.

Linux arm의 실행에는 sched_ext disabled와 모든 대상 thread의 정상 Linux policy를 확인한다. S arm에는 expected ops/instance 및 선택 범위의 실제 SCHED_EXT를 확인한다. 기존 Linux-only guard를 통째로 삭제하여 scheduler arm을 통과시키지 말고 arm별 검증 조건을 명시적으로 확장한다. 다른 arm으로 넘어가기 전 완전한 cleanup과 상태 복원을 확인한다.

[4. 권한/안전 blocker가 있을 때의 사전 분기]

S admission이 권한·환경·기능 문제로 막히면 runtime을 손대거나 위험한 우회로를 시도하지 않는다. timing 시작 전에 아래 Linux-only 축소 계획을 별도 protocol에 고정하고 진행할 수 있다.
- B0_L, F6_L, A_L 세 arm.
- 조건별 6 complete blocks, 각 cohort 3개. 전체 36 measured visits.
- 각 cohort의 3블록에서 세 arm의 위치를 한 번씩 경험하는 Latin 순서를 사용한다. 두 cohort 및 두 조건의 역순을 미리 배치한다.
- bootstrap은 cohort별 3개를 복원추출하고 동일 가중치; n=6임을 명시한다.
- 결과는 E 기여에 한정하고 S/최종 scheduler 포함 검증은 BLOCKED 또는 NOT_RUN으로 남긴다.

이 분기는 timing 전에만 선택한다. full 캠페인이 시작된 뒤 scheduler failure가 발생하면 해당 캠페인은 INCOMPLETE/INVALID로 보존하고 조용히 arm을 줄이거나 표본을 대체하지 않는다. 현재 A의 기존 confirmed 결과는 어느 분기에서도 유지된다.

[5. 정상 full 프로토콜: 한 번의 고정 구성 요소 비교 캠페인]

이 goal의 신규 구성 요소 비교는 한 캠페인이다. 완료 후 작은 p-value를 얻기 위해 반복을 늘리거나 두 번째 캠페인을 임의로 추가하지 않는다. 기존 A/B0 두 캠페인과 별개이며, 새 A_S나 E ablation이 두 번 독립 재현된 것이라고 하지 않는다. 추후 별도 독립 재현이 필요하면 그 필요와 명령만 남긴다.

[6. 정확성, 출처, 실패 규칙]

Timing 전에 각 arm의 두 cohort 자유 생성·cache·DSO·actual worker profile·sensor raw·cleanup을 smoke로 확인한다. 새 로그/fixture의 expected tokens를 그 자리에서 후보 출력으로 교체하지 말고 기존 검증된 B0 oracle을 사용한다.

S가 runtime 수학을 바꾸지 않았다는 이유만으로 output gate를 생략하지 않는다. 모든 warmup/measurement 응답에서 exact tokens와 actual counts를 검사한다. 새로운 all-logits campaign은 필요 없지만 기존 R/A checkpoint와 hash 연계는 유지한다.

F6_L에서 sensor와 shadow pressure가 살아 있고 적격 multi-token Decode만6인지, A_L/A_S에서 실제5/6 선택이 원시 score/guard와 일치하는지 확인한다. 고정6의 기존 single-token5 예외는 오류가 아니다. submitted choice와 actual OpenMP team 로그를 함께 읽는다.

Timeout, output mismatch, wrong model/DSO, wrong policy/affinity, scheduler detach/fallback, mask/tracking failure, cleanup failure, sensor read failure, load range 위반, thermal/resource/environment gate 위반이면 중단한다. 정상 E fallback이나 worker 선택 변화는 사전 규칙대로 유효 표본이다. 느린 pair나 음수 결과는 실패가 아니다.

불완전한 block을 억지로 채우거나 실패 arm을 새 run으로 대체하지 않는다. 모든 planned NOT_RUN과 실패 raw를 보존한다. runner 수정이 필요하면 이전 시도·수정 이유·새 protocol revision을 분리하며 이미 본 성능 결과를 이용한 반복 추가는 하지 않는다.

[7. 분석과 주장 범위]

Primary end-to-end metric:
actual generated tokens / 전체 cohort HTTP wall time.

각 contrast는 같은 condition/cohort/block의 직접 ratio로 계산한다.
gain = 100 * (candidate tokens/s / control tokens/s - 1).
요청8개/생성token을 독립 반복으로 세지 않는다. mean paired gain, absolute tokens/s와 wall time, faster-block 비율, cohort별 결과, paired uncertainty를 제시한다.

정상 full 계획에서는 cohort별4개 block 복원추출, 50:50 가중치의 stratified bootstrap 10,000회, seed20261122, 선형 보간 percentile95%를 사용한다. 후보효과 간 difference/ratio를 계산할 때도 block의 전체 arm pairing을 보존한다. 다섯 contrast를 독립 표본으로 취급하지 않는다. system gate 이외의 다중 보조 비교는 기여 분석이며, CI가 0을 포함하지 않는다는 이유만으로 보편적 인과/가족 단위 오류 보장을 주장하지 않는다.

A_S/B0_L은 scheduler 포함 전체 목표의 직접 비교다. 두 조건 각각 mean>=5%, lower>0%, faster>=6/8이면 한 캠페인 범위의 성공으로 표시하고, lower>=5%는 더 강한 scoped 근거로 구분한다. A_S/A_L이나 A_L/F6_L에 별도5% 기준을 강제하지 않는다.

E 기여는 조건별 positive/negative/inconclusive 및 실제 선택을 같이 보고한다. ambient에서 A/F6 선택이 모두6이면 미소 차이를 worker-choice 효과로 포장하지 않는다. cpu25 결과가 좋더라도 현재 score와 부하가 고정된 범위임을 명시한다. mixed/변동 부하/모든 static 정책 우월성을 주장하지 않는다.

스케줄러 효과가 음수여도 최종 조합의 B0 대비 gain과 분리한다. 전체 goal을 성공시키려고 음수를 숨기거나 Linux-only를 scheduler 포함 결과로 바꾸지 않는다. 기존 A를 실사용/성능 기본값으로 보존하고 scheduler 조합은 연구 구성으로 구분하는 결론도 허용한다.

throughput +26%를 latency -26%라고 쓰지 않는다. wall-time 감소는 따로 계산한다. CPU seconds는 에너지가 아니며 현재 nonstream에서 TTFT/p95 token latency는 측정하지 않는다. slot response timings를 합산한 값을 aggregate phase throughput으로 쓰지 않는다.
